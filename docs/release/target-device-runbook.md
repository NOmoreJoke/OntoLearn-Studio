# 双平台真实验收流程

目标同时为 Windows 11 x64 与 macOS 15 arm64。实际执行先由总控确认设备负责人、精确系统版本/构建号、CPU、内存、干净镜像、独立测试会话、管理员与凭据提示操作边界、可用时段。Server2025 CI、macOS26 CI、当前27开发机和 Linux 均不可替代。以下是待执行驱动规范；没有实际设备结果。

1. 冻结完整 P0 候选与唯一配置、依赖锁、T09 manifest 和受审 SHA；记录构建工具和引擎架构。签名负责人完成真实签名，Mac 完成公证/ticket；记录最终包哈希和组件/动态库/许可清单。签名后字节变化需重新哈希，禁止复用签名前哈希。
2. 恢复批准的干净镜像，记录无用户安装 Node/Python/Docker、无开发依赖和应用残留；系统内置运行时与应用自带运行时另说明。检查不能仅靠 PATH。准备独立证据盘，确认仅使用授权目录；初始磁盘/目录变化清单保留。
3. 按真实下载受众登录渠道（如有）、下载最终候选，保存下载副本 SHA256、受众访问结果、URL及响应元数据；不得在普通日志保留鉴权 query/header。对 Mac 保留真实下载隔离属性和 Gatekeeper 流程，不能用清除 quarantine 绕过。包哈希须等于签名资产。
4. 在批准时段真实安装、首次启动并打开内置案例，观察包内 Python 引擎可用；断网完成 PRD12.1 八步与所有 G 正反例。逐步输出完整对象/事实/轨迹/错误/状态及 T09 baseline/reset 引用。不是仅点击按钮。失败保留原件，退出到最后已提交状态。
5. 由凭据授权人录入合法测试值，在真实 DPAPI/Keychain 后端验证加解密、重启、签名身份稳定升级、密文损坏、锁定/不可用和恢复失败；不可用必须拒绝明文降级。录屏和日志排除录入值，工程师不读取/输出秘密。无资源保留待验，不以 stub 或 Linux 替代。
6. 从真实事务边界分别注入映射/ChangeSet/沙盘崩溃、写盘失败、响应丢失；从独立隔离会话注入渲染无响应并完成真实恢复提示。保留恢复前已提交完整快照，重开后逐项比较，验证不混半批、不自动重放写入。不得禁用 sandbox/hang monitor 或隐藏窗口冒充通过。
7. 分别取消零提交任务和已有轮次任务；保存真实 job/operation/round 标记。取消前提交保留为取消历史，未完成轮次不提交，不能显示全成功。测试时限/队列/分页与上限按真实能力固定；不能因网络/模型失败阻断自动保存。
8. 升级前导出完整可恢复备份并实际还原到另一测试目录；使用实际上一版和新版本安装资产验证格式迁移与签名身份。尚无已发布上一版时，不能编造“升级通过”；由负责人明确可审查的兼容输入版本，仍覆盖迁移故障。卸载保留项目与凭据边界分别记录；重装恢复后比较完整快照，用户未授权目录不改。
9. 按 `migration-recovery.md` 做 Win→Mac 与 Mac→Win 往返，保留两设备各自完整输入/结果、缺依赖提示及继续编辑/重跑/撤销证据。
10. 使用实际模型权限和额度，由 T08/I06 唯一网关执行原版本化评估；记录端点/请求模型/返回标识/可得服务版本/模式/评估哈希，零伪造以及失败定位。不能将协议合成探针当真实服务通过。
11. 主持至少5真人试测，按 `user-study.md` 记录。完成后独立核对证据来源和清单；同候选双指定模型完整新审、实际CI、远端核验及原总控发布决定通过后才分发。

辅助收集脚本只收只读元数据，不能替代上述原生操作。Mac 在批准隔离 Mac15 arm64 会话由负责人运行 `bash scripts/release/collect-macos.sh --approved-isolated-session APP DMG NEW_DIR`；Windows 由负责人在批准目标会话执行 `collect-windows.ps1` 并传入安装包、应用/引擎 exe 和新输出目录。开关仅防误运行，不构成授权。脚本不会启动产品、安装、签名、解锁、调用模型或发消息；结果还需绑定 candidate/baseline/asset 后纳入清单。

Mac 仍需签名负责人检查所有嵌入 Python/动态库，而非只检查外层 app；Windows 在有 SDK 的独立验证机保留 `signtool verify /pa /all /v` 原件、证书/时间戳链，干净机验证真实安装系统策略。目标干净机不要求安装 Xcode/SDK；collect-macos 的 `xcrun stapler` 仅在已有工具时适用，缺工具记录失败并在批准的工程验证机补 ticket 检查，不能把工程机当目标机。
