## 主持脚本

1. 核对资格、同意、匿名ID、实际安装包SHA、候选SHA、设备系统/构建/架构、T09 manifest版本/哈希、reset操作及时间。每名用户使用独立目录并重新还原基线；复测另记，不覆盖首测。工程侧引用T09的 `python3 scripts/verify-product-baselines.py --reset G-base`（或对应G-map-empty/G-behavior/E.5），它仅导出初始JSON，须经批准T01服务创建全新测试项目；输出JSON或seed测试不代表产品reset已接线。
2. 在无模型 API、无开发人员帮助的起点，交给参与者真实安装资产和内置案例。依 PRD12.1 观察安装打开、概念关系/RDF、CSV映射/重复、查询完整/空结果、约束规则失败/修复/依据、行为触发/不触发/幂等、两场景逐轮/指标/重放、迁移任务和HTML报告八段。每段记录真实结果/卡点/帮助来源。固定结果使用 T09 唯一 manifest 的 G/E 文件，不主持人临场补预期。
3. 参与者需要帮助时先指向产品已存在的术语和分级提示。口头解释、外部资料、开发协助、完整示范、Agent完整代做分别记录，禁止主持人代点击后勾“独立”。若不得不接管，记录接管起止和原因，该路径不计无协助成功。
4. 最小迁移任务采用 T09 的 `content/learning/transfer-inputs.json`（待批准集成后使用，核对manifest）。观察参与者独立修复约束错误并解释断言/推导。保留独立尝试结果，再另开重置尝试切项目模式，接受足以完成迁移任务的真实 Agent 完整修改。预期：操作可以完成，独立迁移标记必须为否，学习报告显示 Agent 辅助。不能为做反例覆盖原独立尝试。
5. 记录退出点和主流程严重障碍、用词误解、错误自行修复、迁移解释及导出结果。严重阻断必须处理；T11不能自行缩小P0范围。
