# 审查核心 20 项

来源：`review-policy-20261029/checklist-routing.md`（2026-10-29 已获用户采纳）。本表只决定每次 L1/L2 审查必须覆盖的检查，不代表任何条目已经通过；160 条原始清单的完整性锚点与逐条路由见 [source-checklist-index.json](./source-checklist-index.json) 与 [README](./README.md)。

| ID  | 每次检查                                                           | L2 主责      |
| --- | ------------------------------------------------------------------ | ------------ |
| C01 | diff 是否仅包含获准范围，关联明确 FR/需求，区分局部与结算          | A            |
| C02 | 读取 verify-candidate 结论，base/head/CI tree/政策身份及适用性可靠 | A/B 共用输入 |
| C03 | 实际分级是否正确，有无跨模块/难回滚/风险升级                       | A            |
| C04 | 公共接口和唯一维护者约束是否保留                                   | A            |
| C05 | 输入与错误边界校验、异常返回是否完整                               | A            |
| C06 | 状态变化、重复调用、取消/重试/并发是否正确                         | A            |
| C07 | 数据持久化、事务、历史不变性与恢复是否受影响                       | A            |
| C08 | 权限/信任边界/外联/凭据是否改变或泄露                              | A            |
| C09 | 资源清理、进程/句柄/临时文件、失败路径有无遗漏                     | A            |
| C10 | 依赖与配置变更的兼容性/供应链/锁文件是否一致                       | A            |
| C11 | 需求断言是否真实，测试能发现相应错误而非复写实现                   | B            |
| C12 | 正向、反向、边界及原缺陷回归覆盖是否充分                           | B            |
| C13 | E2E/跨模块流程是否使用真实接口，有无替身冒充                       | B            |
| C14 | Windows/macOS、打包与实际运行证据是否匹配所宣称范围                | B            |
| C15 | 失败/跳过/取消/未知是否如实保留且影响已处理                        | B            |
| C16 | 加载/空/错误/输入保留/可访问性等用户状态是否受影响                 | B            |
| C17 | 性能/容量声明是否有对应环境与测量，未测不量化                      | B            |
| C18 | 日志、证据、导入导出是否含敏感数据或误导完成声明                   | B            |
| C19 | 审查意见及修复验证是否闭合，增量范围/range-diff 是否支持本轮复用   | B            |
| C20 | 文档/迁移/回滚/交接与实际行为是否一致，完成口径是否越界            | B            |

L1 指定审查员覆盖核心 20 项及适用模块；L2 按主责分工，不能由 A/B 共同忽略接口边界。仅 C02 共用机械输入（verify-candidate JSON），各自必要的上下文不视为重复全审。
