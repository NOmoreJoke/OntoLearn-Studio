# 全文读取与回读收据计划

本文件是下一轮执行计划，不是已读证明。固定107逻辑条目不删、不改：104个文本路径分别literal全读，3个归档的75个文本成员也分别全文读。全部页只由02a固定Git字节连续切分，不加标题、编号或末LF；每页最多6144B及64个物理行。路径、半开字节区间、物理行、末LF、页及源hash见`scope-107-read-plan.json`。默认不去重，不以脚本只输出hash、结构摘要或代理摘要冒充审者全文读取。

## 实际读法

1. 未来owner在独立setup授权后，将共同页archive解到本方repo同级的`runtime/input`，核页文件与源02a逻辑文件的完整字节关系；不放入repo，不改prettierignore。此步骤本轮未执行。
2. 新审者先实际读本方完整full-input连续页，再读所有共享准备说明和19项source绑定；然后按107清单顺序逐页读取。每次只请求足够小的明确页/范围，保留原公开Read调用和模型可见返回。
3. 对每项核实际返回覆盖了所有页、页内所有内容及独有元数据。任何输出截断、页内缺段、区间空洞、UTF-8/换行无法判定、来源不符均记`GAP/UNKNOWN`；仅补实际缺段，不用prepared正文填补实际返回。
4. Read工具可能加行号、截断提示或规范化末LF。去编号是`DERIVED_RENDERING`，必须记精确可逆变换及实际元数据；若工具未暴露末LF，不从expected推实际。模型可见文本、工具details全文、实际文件/hash分别记录，details里有全文不等于模型看完。
5. 归档逐成员核名/bytes/hash之后，还须逐成员实际读文本页，特别保留失败原件。75个成员hash通过不等于75个文本已读；归档外另列的缺失首38原件仍UNKNOWN。
6. 最终逐路径填实际callId、返回字节/hash、截断和覆盖方法；分别报告`logicalScopeCovered`、`literalPathsRead`、`DERIVED/SAME_BLOB`项数及`GAP`。不得从prepared页生成、107个hash通过或报告自述推实际FULL。正文读完、工程结论、正式终态、完整报告与发布门各自独立。

可选去重须在实际读回证据形成后逐路径如实登记，不能预填已读。只有全内容精确相等且路径/大小/换行/来源等元数据完整时记`SAME_BLOB`；只有精确变换、无缺段及独有元数据全部覆盖时记`DERIVED`。二者均不能计作新的literal读取。该机械关系不是“结构相似即可替代”，也不是预授本轮默认去重；默认仍读全部21页。
