# OntoLearn Studio 原型与 PRD 一致性审核报告

> 审核对象：`OntoLearn-Studio-Prototype.pen`（40+ 画板，覆盖 01 首次启动 → 09 报告导出 → 10 响应式/全局状态）
> 对照基准：`PRD-本体学习与落地Agent工作台.md`（V0.6，含附录 A～G，附录 C/E 为能力边界与执行语义主定义）
> 审核方式：解析 .pen 文件 JSON 结构（含 ref 组件引用与 descendants 覆写），逐屏提取全部文本内容，与 PRD 条款逐项对照
> 审核日期：2026-10-18
> 结论版本：V1.0

---

## 0. 总体结论

原型与 PRD V0.6 的吻合度**很高**：

- 六模块闭环、8 步工作台导航、一级导航（学习首页/我的项目/模型与隐私设置）完整呈现；
- 附录 E.5 固定沙盘模型的逐轮数据（W001～W016、积压 1/2/3/4、累计 3/6/9/12；产能 4 全清、累计 4/8/12/16）**逐格一致**；
- 附录 G 的行为冲突（B-05）、稳定排序（B-06）、未触发原因（B-02）、G-base 领域数据均正确落实；
- FR-902 外发授权六要素、FR-1000 导出能力三标识的条件逻辑等高风险语义逐条落实；
- V0.5 新增条款（B-06 稳定排序、冻结快照口径）与 V0.6 新增条款（"Agent 完整代做不计独立迁移"）均已同步进入原型，说明原型基于最新版 PRD 制作。

但审核发现 **2 处与 PRD 条款直接不符、9 处原型内部不一致、5 处 P0 覆盖缺口、3 项待澄清**，问题集中在共享壳组件（底部状态栏、Agent 面板、徽章）未按页面覆写。

## 1. A 类：与 PRD 条款直接不符（建议修改原型）

### A-01 多数工作台页面缺少"单一主动作"

- **违反条款**：8.3 单一主动作（并影响 8.2 统一工作台布局的"底部：……下一步"）
- **现象**：底部反馈栏的 `[Next Primary Action]` 槽位在全部 24 个工作台屏幕均为空（.pen 文件中 0 处 descendants 覆写）。导致约一半屏幕没有任何主动作按钮：
  - 03 数据映射-预览执行（应有"执行映射"）
  - 04 查询-模板与可视化（应有"执行查询"）
  - 05 项目检查总览（应有"运行检查"）
  - 07 沙盘-场景配置（应有"运行场景"）
  - 09 导出项目包（应有"导出项目包"）等
- **关键证据**：PRD 8.3 点名的四个主动作示例——"预览映射、执行查询、运行检查、比较场景"——在原型中一个都没有出现。
- **建议**：为每个引导页面的底部主动作槽位或页面头部补充唯一 Primary 按钮，并与 PRD 8.3 的示例动作命名对齐。

### A-02 查询 SPARQL 的谓词与本体定义矛盾

- **违反条款**：FR-201（用户必须能够通过实际 RDF 核对生成结果）、8.9（中文业务术语与英文技术标识应建立稳定对应关系）
- **现象**：
  - "02 本体构建-关系与事实"定义 `:hasAlarm`（`rdfs:domain :Equipment`、`rdfs:range :Alarm`，方向为**设备→告警**）；
  - "04 查询-模板与可视化"与"04 查询-结果"的 SPARQL 却写 `?alarm … :fromEquipment ?equipment`——**谓词名不同、方向相反**，且 `:fromEquipment` 未在任何界面定义过。
- **建议**：统一谓词与方向（推荐查询改为 `?equipment :hasAlarm ?alarm`），或在 02 概念表/关系定义中补充 `:fromEquipment` 的定义与说明。

## 2. B 类：原型内部不一致（占位符未按页面更新）

> B-01 ～ B-04 为同一根因：共享壳组件在全文档 0 处覆写，可一次性批量修复。

### B-01 底部状态栏与页面内容矛盾

- **现象**：所有工作台屏幕固定显示"修改记录 0 · 可撤销 / 检查：尚未运行"，但：
  - "05 项目检查总览"页面本身已展示完整检查结果（需要修复 1 / 建议改进 2 / 新知识 1 / 不支持 1）；
  - "07 沙盘-运行详情"已显示运行成功、可重放；
  - "09 成果与运行记录"已有多条历史运行。
- **对照**：1280 响应式版反而正确显示"当前 · 检查已运行"，证明覆写机制可用且文案本应存在。
- **建议**：按各页面实际状态覆写底部状态栏。

### B-02 Agent 消息未按页面场景更新

- **现象**：全部屏幕（含沙盘、行为、导出页）都显示同一条"这个页面先回答'我们要解决什么业务问题'……暂时不需要理解 RDF 或命名空间"。
- **违反方向**：FR-801 要求"每个页面应根据场景"提供上下文动作与内容。
- **建议**：每个模块的 Agent 消息按当前页面任务重写。

### B-03 Agent 模式徽章显示占位文本"状态"

- **现象**：Agent 面板头部的模式徽章引用 Badge / Info 组件，全文档无覆写，显示占位词"状态"。
- **建议**：应显示"导师模式/项目模式"（FR-802 的两种模式目前在原型中无任何可视化呈现，顺带补齐该缺口）。

### B-04 顶栏"自动保存"徽章显示占位"状态"

- **现象**：同 B-03，Autosave Status 徽章显示"状态"。
- **对照**：1280 响应式版正确显示"已自动保存"。
- **建议**：统一覆写为"已自动保存"或按实际保存状态显示。

### B-05 业务概念计数矛盾

- **现象**：侧边栏"业务概念 4"与"09 HTML 项目报告"中"4 个类"一致（符合附录 G-base 的 4 个类：Equipment / Alarm / WorkOrder / HighRiskEquipment），但"02 本体构建-概念表"列出 **5** 个类（多出"运维人员 Person"）。
- **说明**：PRD 4.3 案例流程确实提到"建立设备、告警、**人员**、维修工单等概念"，Person 有出处；但附录 G-base 冻结的是 4 类。
- **建议**：三处取齐——若保留 Person，同步修改侧边栏计数与报告概况文案；若不保留，从概念表移除。

### B-06 映射字段与预览 RDF 矛盾

- **现象**：
  - "03 数据映射-配置映射"映射了 4 个字段（equipment_id / equipment_name / **install_date** / enabled）；
  - "03 数据映射-预览执行"的输入样本表和生成 RDF 只有 3 个字段（无安装日期），"新增事实 6 条"按 4 字段配置应为 8 条；
  - "10 响应式-1024 数据映射"的映射卡片又显示 install_date。
- **建议**：预览页补齐 install_date 列与对应 RDF 三元组，修正事实计数。

### B-07 "08 Agent-Diff基准过期"版本显示矛盾

- **现象**：正文说明"当前项目 V1.3"，但顶栏项目上下文仍显示"项目版本 V1.2 · 输入快照 S-2026-10-17"。
- **建议**：该屏幕顶栏应覆写为 V1.3，强化"基准已变化"的视觉一致性。

### B-08 快速介绍流程缺一步

- **现象**："01 首次启动"入口文案（"用 2 分钟了解**六个模块**如何串联"）与"01 快速介绍"副标题（"同一个项目贯穿**六个模块**"）都宣称六模块，但流程图只有 5 步：明确问题 / 建立概念 / 连接数据 / 提问验证 / 行动推演——缺少"检查并发现新知识（推理）"环节。
- **建议**：流程图补第 5 步"检查与推理"（行为推演顺延为第 6 步），或将文案改为与实际步数一致。

### B-09 我的项目统计与列表不匹配

- **现象**：统计卡合计 10 个项目（进行中 3 + 已完成 5 + 已归档 2），列表仅 4 行（设备运维教学案例 / 园区能耗 POC / 课程练习·告警质量 / 旧版示例项目）。
- **建议**：补齐列表行或调整统计数字，保持演示数据的自洽。

## 3. C 类：P0 覆盖缺口（PRD 有要求、原型未呈现）

> 以下不一定是设计错误，但作为 P0 需求应在原型中有对应表达，供评审确认交互方案。

### C-01 项目"重命名"入口缺失（FR-002）

FR-002 要求支持"新建、打开、复制、**重命名**、归档和导出项目"。项目列表行操作只有打开/复制/归档，头部有导入项目包/新建项目，"我的项目"页面无重命名入口。

### C-02 "自然语言查询草稿"入口缺失（FR-400）

FR-400 要求四种查询入口：常用问题模板 ✓、基础可视化查询 ✓、SPARQL 编辑器 ✓、**配置模型后的自然语言查询草稿 ✗**。查询页无 NL 入口（哪怕以"需配置模型后可用"的禁用态呈现亦可）。

### C-03 "最小外发调用记录"无入口（FR-904）

"08 模型与隐私设置"展示了服务配置、能力验证三区分、隐私三档，但 FR-904 要求的本地最小外发记录（目标服务、用途、数据范围、授权结果、时间）没有查看入口。

### C-04 保存查询对话框未设计（FR-404）

FR-404 要求保存查询的名称、说明、SPARQL、数据范围和关联能力问题。原型仅有"保存查询"主按钮，无对应对话框/表单界面。

### C-05 概念行级"复制/删除"操作不可见（FR-200）

FR-200 要求类、属性、个体等的"创建、编辑、**复制和删除**"。概念表每行只有"编辑"；右侧详情面板虽有"删除前影响：8 处引用"文案（暗示删除流程存在），但无删除/复制按钮入口。

## 4. D 类：需澄清/低优先级

### D-01 数据范围选项的语义并列

"04 查询-模板与可视化"的 Scope Options 将"本地只读 · 禁止外联"与"断言事实 / 断言事实＋当前推导结果"并列展示。PRD 中只读+禁外联是**执行约束**（FR-402），不是**数据范围**（FR-401 仅两档）。若渲染为第三个单选项会造成语义混淆；若仅为状态徽章则无碍。建议确认控件形态。

### D-02 "未闭环高危告警 4 条 → 0 条"的统计口径

"07 沙盘-场景对比"显示该指标随产能提升清零，隐含"工单完成即关联告警闭环"的假设。但附录 E.5 固定模型只定义了工单创建与完成，未定义告警状态转移。建议在附录 E.3/E.5 或原型注释中补一句口径说明，避免开发实现时各自解释。

### D-03 杂项清理

- 残留空测试画板 `Save Test`（200×100，无内容）未删除；
- "10 响应式-1024"顶栏缺产品名"OntoLearn Studio"（1280 版有）。

## 6. 修复优先级建议

1. **第一批（影响开发理解交互骨架与数据模型）**：A-01 主动作缺失、A-02 SPARQL 谓词矛盾。
2. **第二批（同一根因，批量覆写壳组件即可）**：B-01 ～ B-04。
3. **第三批（数据自洽）**：B-05 ～ B-09。
4. **第四批（下一轮原型迭代补齐界面）**：C-01 ～ C-05，同时确认 D-01 / D-02 的产品口径。

## 附：审核方法说明

- 使用脚本解析 `.pen` 文件（JSON 格式），构建全文档 id 索引后递归解析 `ref` 组件引用与 `descendants` 覆写（含嵌套注入内容中的二级 ref），按屏幕输出全部文本节点，共提取 52 个画板、5277 行结构化内容。
- 共享组件覆写情况通过统计目标节点 id 在全文档 `descendants` 中的出现次数验证（Agent 消息 / Agent 模式徽章 / 底部状态 / 主动作槽位均为 0 次）。
- 本审核聚焦**内容与语义一致性**，未覆盖视觉还原度、间距、配色等纯视觉维度。
