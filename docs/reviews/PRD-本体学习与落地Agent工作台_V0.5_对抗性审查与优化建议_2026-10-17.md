## 两项可选优化

### O01：让 M0 的验收基线清单覆盖本版新增基线

**依据：** [M0 退出条件](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:855) 目前点名“附录 C～E 及 G-base 冻结”；[附录 G](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1116) 实际还包含 G-map-empty、G-behavior，并依赖 E.5 的固定沙盘模型。

**潜在影响：** 如果团队只按里程碑表制作交接清单，可能只锁定领域基线，而让映射、行为和沙盘样例使用不同版本。正文已有版本化要求，因此这是交接表述的优化，不是新增正确性缺陷。

**最小修改建议：** 将 M0 退出条件中的“G-base 冻结”改为：

> 冻结用于验证附录 C～E 的案例基线清单，至少覆盖 G-base、G-map-empty、G-behavior 和 E.5 固定模型；清单记录数据、规则、行为、场景配置和预期结果的版本，后续测试引用该清单。

此处冻结的是输入和预期结果，不要求 M0 提前完成 M2/M3 的产品实现。已有这些文件时，直接登记其版本即可，无需重新制作一套材料。

### O02：在学习测试中覆盖“Agent 完整代做”的归类

**依据：** [FR-104/105](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:297) 区分操作完成和独立迁移成功；[FR-802](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:513) 允许项目模式生成完整草稿与修改建议；第 765 行定义独立迁移成功率。

**对抗场景：** 用户做迁移任务时切到项目模式，接受 Agent 完成该任务所需的完整 ChangeSet，但没有点击“完整示范”。如果实现仅根据示范按钮使用记录和最终状态判定，可能把这次完成算成独立迁移成功。

“独立完成”的现有要求已经排除了这种情况，因此不能仅凭 PRD 认定产品会错误计分。建议在既有学习效果测试脚本中明确覆盖这一路径。

**最小补充建议：**

> 在未完成的迁移任务中切换到项目模式，接受足以完成该任务的 Agent 完整修改。预期：操作可以标记完成，但该次尝试不得计入独立迁移成功；学习报告应反映使用了 Agent 辅助。

该样例只验证现有学习分类语义，不要求禁止项目模式，也不把所有概念提示或部分帮助一概视为完整代做。

## 后续验证的边界

首发平台、单一主成功标准、推理支持范围和沙盘类型，仍分别由 Q2/Q3/Q6/Q7 决策；容量、参考设备、团队排期及受测模型服务也已有对应条目。本轮没有依据替这些事项做业务决定。

学习验证可沿用 [M1 的既有退出条件](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:856)，先观察初学者能否离线完成建模与查询、找到下一步并修复错误；M4 再执行第 11.2 节完整验收。这样能较早发现需要口头解释的卡点，不必等六模块全部完成后才观察用户。

建议在后续审查中用具体实现反例、测试失败、用户卡点或范围变化作为修订依据。当前阶段最有价值的新证据，是第 17 节已有交付物及其验证结果。
