# T08 指定审查发现的独立技术分析（2026-10-23）

结论：返回身份缺少会话放行检查、无工具思考字段未强制、usage 未约束响应、失败投影无分类码等行为均能复现；但必须分别判断它们与当前私有模块契约的关系，不能直接把所有现象等同完整产品缺陷。建议优先补返回身份的执行前检查，明确 enabled 模式的字段规则，拒绝响应声称的输出超额，并可增加安全枚举失败分类。不得把输入/总 token 与现有“已请求输出上限”混作同一预算，也不得自动归一化模型版本或选中对象顺序。

**原审方 P1/P2 严重度与整体 NotPass 全部保留。本分析不自行降级、关闭任何指定审查发现，不代替原审方复核或完整验收。** 以下“契约争议”说明技术依据及待裁定点，不是关闭状态。

## M P2-2：响应身份固定（原 P2，未关闭）

**位置与触发。** `deepseek-codec.ts:124,148–171` 只校验返回 model 是有限非空串；`conversation.ts:157–180` 在解码后直接进入工具执行，`194–197` 才把 model/fingerprint 回传。`capabilities.ts:39–70` 虽能比较受测 signature，却没有被会话调用。有限反例返回 `different-returned-model`，仍进入 ready，且注入端口实际被调用一次。

**契约判断。** codec 负责解析、暴露返回标识而非证明受测能力，按设计第 16 行它本身接受不同返回标识并不错误；纯会话也尚未声称已获模型 ready 授权。但运行入口没有强制的受测身份前置，构成真实的执行前检查缺口。它目前没有生产调用点并不能替未来接线保证这一点；FR-900 的一种受测服务及设计第 73 行的正式模式固定仍不能验收通过。

**建议最小 patch。** 由宿主传入严格、只读的预先受测 baseline，在会话解码后、任何工具执行或答案接纳前核对 `returnedModel` 与 `fingerprint`，并核对会话 mode/effort/codecVersion 与该 baseline 的一致性；不符则停止，保留已有本地收据。baseline 缺失不能自动由首次响应生成。codec 解码器可继续支持能力探测，不必硬写 `response.model === REQUEST_MODEL`：请求别名与受测返回串可能不同。不得用忽略版本后缀、模糊匹配或缺 fingerprint 自动通配来消除漂移。私有失败可先使用 INVALID_PROTOCOL；是否新增专用私有码由主写者统一决定。

**必要验证。** 合成受测返回串匹配时可继续；不同 model、fingerprint 改变/消失、baseline 与 mode/effort 不符时端口调用为零；baseline 快照不可反写；先有成功草稿再漂移仍保留旧草稿。真实返回身份、配置/端点/主体绑定与质量 ready 仍须 I06/正式评估，纯字段相等不能证明实际权重。

## M P2-3：无工具时缺 reasoning_content（原 P2，契约争议未关闭）

**位置与触发。** `deepseek-codec.ts:63–69` 和 `conversation.ts:160–166` 均以 enabled **且有工具**为必填条件；assistant schema 在 `21` 行允许字段缺失或 null。无端口、enabled、响应无 reasoning_content 时会话接受答案；追加问题后下一请求仍明确 `thinking.type=enabled`、`reasoning_effort=high`，历史 assistant 没有 reasoning_content。

**契约判断。** 该反例确证字段未强制，却不能证明请求静默退成 disabled。当前设计第 12、83 行明确把必需保留/拒绝条件限定为“携带工具时”，现有 `t08-codec.test.ts:72–87` 与 `t08-conversation.test.ts:145` 后的测试符合这一契约。PRD 没有单独规定无工具响应的 reasoning 字段。因此按当前私有明文契约，尚不能把此现象直接判作已证实违反；更宽的“不可默默退模式”要求及真实 provider 是否应返回该字段仍是争议依据。

**可采纳的保守 patch。** 若本线明确收紧为“enabled 的每个 assistant 都必须提供 string reasoning_content”，同时去除两处工具数条件，保留现有字段并更新设计/反例；缺失或 null 在任何工具/答案处理前失败。不要伪造空字符串补字段，也不要为绕过检查改 mode。是否把空字符串也判非法需另行明确协议，不从缺字段反例推导。disabled 模式无需强制删除已有历史 reasoning；历史回传仍受 I06 最终授权。

新增无工具 enabled 的缺失/null/合法字段、历史往返及 disabled 对照即可验证本地新规则；不能据此宣布真实模型模式已验。原 P2 保留，等待实际 patch 与指定审方复核。

## M P2-4：usage 与预算（原 P2，需拆分裁定）

**位置与触发。** `conversation.ts:19–21,110–124` 只累计每次请求的 maxTokens；`194–197` 仅回传 usage。`deepseek-codec.ts:100–118` 检查非负整数与总和一致，不与请求上限比较。有限观测：maxTokens=1、累计已请求上限=4 时，prompt=1699999/completion=1/total=1700000 被接受；prompt=10/completion=100/total=110 也被接受。

**契约判断。** 两个反例不能合并：

- 大输入、completion=1 并未违反现有“已请求输出 token 上限”。设计第 85 行明确排除输入 token 与费用核算，并将实际总 token/费用硬限额留给 I06。将 total_tokens 与 maxTotalRequestedTokens 直接比较会改变单位和契约，误拒合法长输入。
- completion=100 超过这笔实际请求的 max_tokens=1，却仍被接受，是真实的响应一致性检查缺口；至少应在工具/答案副作用前拒绝这种自报输出超额。请求上限是发送参数，不保证 provider 遵守；解码后的 usage 也不是可信账单。

**建议最小 patch。** 保留现有 requestedTokenCeiling 的准备时占用、失败不退还与跨问题不重置；若响应有 usage，在会话执行工具前比较 completion_tokens 与该笔 maxTokens，超额拒绝。需要累计实际输出时使用独立明确命名的计数和界限，整数采用安全整数检查，缺失 usage 记 unknown 而非零。不要把 total_tokens 硬塞进现有输出请求预算。若本线决定新增实际输入/总 token 上限，必须使用独立宿主配置、明确缺失 usage 的处理与下一请求阻断，不能沿用旧字段含义。

**必要验证。** completion 超请求值在端口执行前拒绝；同预算下大输入且输出未超额不误拒；usage 缺失保持明确未知；累计请求上限仍不回退；超额失败保留已有收据。真实费用在响应收到前可能已发生，本地事后比较不能充当 I06 的发送前硬预算或退款保证。原 P2 的真实总费用/输入限额部分仍为接口依赖，不因上述小 patch 自动关闭。

## M P2-5：安全失败码投影（原 P2，契约争议未关闭）

**位置与触发。** `agent-service.ts:262–268` 宿主收据保存固定 failure code；`316–327` 对非 evidence 统一只发 kind。TIMED_OUT 的投影确为 `{"kind":"failure"}`。`t08-agent.test.ts:134–146` 明确锁定不回传异常/草稿正文。

**契约判断。** 当前实现如实回传“失败”，完整码仍在宿主/UI，宿主完整收据规则也不允许失败被模型隐藏。附录 F“工具失败必须返回失败”没有明确要求把每个安全码交给 provider；故不能仅据码被省略认定违反当前私有最小化契约。另一方面，分类有助于模型区分不可重试与暂时失败，属于可采纳的协议改进；不表示 provider 可以自行重试或越权重取上下文。

**建议最小 patch。** 单独处理 failure，仅加入有限枚举 code 或更窄的失败分类，draft 仍只有 kind。运行时从本地安全枚举校验/映射，未知值回退 TOOL_FAILED；不能直接透传任意字符串、错误 message、stack、路径或业务内容。即使 TypeScript 声明为 AgentErrorCode，运行时来自适配器的异常仍不能因此获得无条件回显。主进程完整收据与 UI 状态不删减。

**必要验证。** 超时/取消/失效/参数错误得到预期安全分类；原异常正文、非法 code、草稿详情不进投影；kind/tool_call_id 保持正确；所有投影字节仍交 I06 最终授权，安全枚举不自动获得外发权限。真实 FR-806 的用户入口及重试策略仍未验。
