## 独立补丁审查中追加的真实问题

`independent-patch-review-1.md` 对第一版 WIP 给出暂不通过：尽管构造器净化 code、provider投影净化，untyped adapter仍可构造合法AgentError后运行时篡改readonly code，自由文本被原 `executeOne catch` 直接写入本地完整收据。这个问题不是指定模型的原发现，单独记录，不能回填成其意见。

最小修复为 `normalizeAgentError`：在try/catch中读取外国实例的code，经安全枚举后构造新实例；getter/proxy读取失败使用固定fallback。`executeOne`在本地收据入账前应用，conversation的两处catch同样不保留外国异常实例。新增“篡改code”和“抛异常getter”反例，验证本地收据仅TOOL_FAILED且无secret。原独审1及其修前hash/反例保留，修后另有复核2，不把先前737TS/1052Py成功当这个问题已不存在。
