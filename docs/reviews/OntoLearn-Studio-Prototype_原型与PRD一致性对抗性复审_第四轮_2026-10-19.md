## 3. 残留 3 项的精确修复规格

三处问题同根因：占位文字位于 AppShell 壳组件**内部的嵌套 ref**（徽章组件实例）中，屏幕级 descendants 覆写不易直接触达其内部文本。提供两条修复路径，任选其一。

### 3.1 路径 A（推荐）：直接编辑 AppShell 组件本体

三处文案在绝大多数屏幕取值相同，直接修改 `Component / AppShell` 内部即可一次修复 30+ 屏，无需逐屏覆写：

| 节点（id → 引用目标） | 当前渲染 | 改为 | 说明 |
|---|---|---|---|
| Autosave Status（`SvPUC` → Badge/Success） | 状态 | **已自动保存** | 1280 响应式稿已有此文案，直接对齐 |
| Agent Mode Badge（`VVbfi` → Badge/Info） | 状态 | **导师模式** | 08 Agent-Diff 两屏可另行覆写为"项目模式"（对应 FR-802 两种模式） |
| Bottom Status（`bybVu` → Badge/Neutral） | 状态 | 删除该徽章，或统一改为**项目状态** | 其后两行状态文案已按屏覆写（V2.0 修复），徽章仅承担类别色标职能 |

### 3.2 路径 B：逐屏嵌套覆写（仅当需要按屏差异化时）

在每屏 descendants 中对目标 ref 写嵌套覆盖，形如：

```json
"VVbfi": { "descendants": { "FUiuL": { "content": "导师模式" } } }
```

与现有 `bhL4U` 的 enabled 覆写走同一编辑入口（注入内容区的徽章 ref——如"任务 1 / 8"——已验证该机制可行）。
