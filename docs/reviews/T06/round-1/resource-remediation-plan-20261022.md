# S1 资源问题处置方案

对象为冻结产品 `61396a598b2dffc1d3d2fd4660f9af1d5c93d266`。MiniMax 原报告 `minimax-m31flash.md`（25539B，SHA `1404505d57ec6310f1a0d62646f63441a03913afd895aaa5772c0166be1f90b5`）为有条件通过，含两项 P2；不能当作指定双审通过。原报告、真正最终消息、turn_completed/finished 和工具原件封存后，才修改本线独占实现生成后继候选。当前方案不是修复完成或性能验收。

## 两项事实与成本边界

1. 原算法把所有单值写意图两两比较，包含不同对象/属性的无关组合；每次 `_put` 又扫描并序列化全部事实，每个候选动作还排序并序列化完整状态。写意图数 W 不等于源动作数 A：一个 create 可以包含多个 initial 字段。原报告实测 800 creates × 50 initial 为119.4秒；这是该次环境/命令的测量，不是产品容量阈值。
2. 当前接口要求完整条件决定集合，每个行为与接受事件组合各有一条决定。B 个行为和 E 个事件因此至少有 B×E 条输出。原报告1000×1000为100万条、峰值346MB。维持当前 JSON 字典/列表接口时，输出所需时间和内存均有 Ω(B×E) 下界；不可把必要输出成本称为已优化掉。PRD Q5尚未规定参考设备、数据规模或内存/时间阈值，本线不能编造验收线。

原脚本核对后的测量口径：probe17 的每个 create 有50条对同一 `status=S1` 槽的重复 initial，并非50个不同属性；8.1/30.0/119.4秒仅对应其精确200/400/800输入。probe18 的346MB是 **tracemalloc 跟踪的 Python 分配峰值**，并非RSS，10.7秒计时也开启了tracemalloc，不能称无跟踪常规耗时或生产容量。精确脚本、首失败、修正、全部后台日志和原返回已归档；后继测量须同口径比较，另列无跟踪时间/RSS时明确方法。此口径纠正将进入后继双方共同历史，不改原报告数字、不降低两项P2。

## 最小后继实现

- 用每次调用私有、生命周期有界的工作区编辑索引：对象 ID 集合、按规范 JSON 键登记的事实及 subject/property 槽位索引、通知身份集合。写入和重复判断只访问受影响槽位；删除对象时同步维护其事实及关系入边。只在导出候选/事件后状态时生成规范排序的普通 JSON，保持输入脱离、状态集合、通知顺序和错误位置。
- 动作 changed/unchanged 根据该动作真实受影响内容判断，替代每步比较完整候选 JSON。create 仍是一源动作；同实例有序覆盖、跨实例任何不同值竞争、同值仍保留其他动作均保持。失败不返回部分候选，原消费和输入不变。
- 单值意图按 subject/property 分桶；每条预计算保留 JSON 类型的值键。桶内只为冲突搜索保留每个 `(event_id, behavior_id, value_key)` 最早原写意图，保留完整 intents/trace。全同实例或全同值的桶跳过。其余按原写序定位第一个跨实例异值对，跨桶选全局 `(left_index, right_index)` 最小者，保持原 combinations 的第一冲突与完整错误证据。
- 推导事实合并只构建一次既有事实键集合，避免每条推导重建全量集合；校验仍拒绝单值矛盾。
- 保留每个 B×E 决定及完整字段、顺序、独立 JSON 容器。仅消除绑定/副本/查找等重复工作，不新增配额、分页、删矩阵或更改未触发原因。必要输出内存与 Q5待定仍如实记录，由后继两个指定模型重新判断该资源问题是否关闭。

去重只用于寻找冲突，不删除动作。正确性理由：若某桶最早的不同 `(instance,value)` 项与所有后项均不冲突，后项只能是同实例异值或异实例同值；排除全同实例/全同值后两类必同时存在，第二个不同项必与另一类冲突。因此可在线性扫描内找到该桶与原两两算法一致的最早冲突；必须比较跨桶全局原索引，不能直接返回字典中的首桶。

- 所有未关闭项保留原严重度及证据；不提前把资源 P2降级，也不沿用旧 ZCode Pass。
