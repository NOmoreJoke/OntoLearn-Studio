## 1. 审查结论与边界

**V0.2 已实质修复上一轮的大多数缺口，尤其是离线教学、约束与规则编辑、结果过期、映射原子替换、Agent 事务及最终外发检查。现在主要需要修正新增条款之间的冲突，以及少数仍不能唯一验收的边界。**

本轮保留 **6 项修改意见：3 项高优先级、3 项中优先级**；另有 **2 项建议补充**。优先级只表示本次审查的处理顺序，不对应 PRD 的功能 P0/P1。

- **高优先级**：A01 同轮写冲突与工单正常流转相撞；A02 行为可能读取事件更新前的推导结果；A03 完整项目包未明确携带断言事实及映射来源所有权。
- **中优先级**：A04 数据导出与敏感正文验收冲突；A05 验收基线缺少设备与用例重置定义；A06 模型接收端变化后的授权失效规则不清。
- **补充建议**：A07 冻结规则组合语义；A08 补 HTML 报告的安全显示边界。

建议先处理前三项，再冻结沙盘和项目包相关实现；M0 的其他独立验证可以继续开展。此次不建议增加新的业务模块，也不建议推翻六模块闭环。

审查依据包括全文逐条对照、两个独立 Agent 分别审视领域语义和产品/Agent 边界，以及最小反例推演。A01/A02 用独立的简化脚本核对逻辑，不是产品代码测试；没有运行真实应用、引擎或安装包，不能据此认定存在实际数据泄露或实现故障。原 PRD 未修改。

## 2. 六项主要修改意见

### A01｜高：同轮写冲突规则会阻止工单在创建当轮完成

**性质：明确的条款冲突。**

**原文位置：** [FR-602，L455](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:455)、[E.1，L1002](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1002)、[E.2，L1016](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1016)、[E.3，L1023](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1023)、[E.5，L1048](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1048)。

目前规则将“同一轮、同一对象、同一属性的多个不同写入”视为冲突并回滚；但工单又需要在同一轮先进入待处理队列，再由资源阶段处理完成。

**最小反例：** 第一轮创建 W1～W4，状态为“待处理”；产能为 3，资源阶段将 W1～W3 改成“已完成”。这三张工单都在一轮内经历了不同状态写入。若按全轮冲突规则检查，本轮失败；按 E.5，却必须成功得到“积压 1、累计完成 3”。两条要求无法同时按字面满足。

**建议替换 FR-602/E.1 的冲突定义：**

> 冲突检查用于同一行为阶段、基于同一条件快照生成的竞争写入。多个行为试图对同一对象的同一单值状态写入不同值时，本轮失败。事件、行为、资源等不同阶段之间，符合已声明状态转移规则的顺序更新允许执行，不视为竞争写入。多值关系的追加与单值属性的覆盖分别定义。

这不要求引入并发行为执行；即便实现按顺序执行，也应检查同一阶段各行为的写入意图，避免排序掩盖冲突。

**新增验收：**

- 正常路径：同轮“创建待处理工单→资源阶段完成”成功，第一轮积压 1、累计完成 3。
- 冲突路径：两个行为在同一行为阶段将同一工单状态分别改为不同值，本轮失败且全部回滚。

两组验收应同时通过，避免为了修复正常路径而取消真正的冲突检查。

### A02｜高：行为读取推导事实的时点，与本轮事件更新不一致

**性质：跨模块执行语义缺口，可造成错误触发或漏触发。**

**原文位置：** [FR-701，L473](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:473)、[附录 C，L947](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:947)、[E.1，L1000](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1000)、[E.2，L1010](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1010)。

能力矩阵允许将推导事实作为行为输入，但固定执行顺序是“事件→行为→资源→推理”。即使界面已经很好地标记结果过期，也还需要规定行为实际读取哪个推导快照。

**最小反例：**

1. 初始设备 001 没有风险分类。
2. 本轮 E01 为其新增一条 High/Open 告警。
3. 行为条件是“事件对应设备属于 `HighRiskEquipment`”。
4. 行为阶段读取上轮推导，条件为假，不建单。
5. 本轮末才推导出高风险。

本轮行动已经落后于事实；若未触发事件不再重试，还可能永久漏单。反向场景也成立：移除唯一风险依据后，行为仍读取上轮高风险分类而误触发。这里不认定 PRD 已规定未触发事件一定被消费，而是指出该规则也未消除本轮读取旧推导的问题。

**建议优先方案：** 将每轮顺序调整为：

> 应用事件 → 形成该状态对应的推导快照 → 基于同一冻结快照评估全部行为条件 → 执行动作 → 资源处理 → 更新最终推导 → 计算指标并提交。

同时明确初始场景所用推导与初始断言一致；行为后产生的新事实不在当前轮再次激活行为，保持既有“禁止同轮级联”边界。

**更窄的替代方案：** P0 行为条件仅允许读取本轮断言事实。若选择此方案，必须同步收窄附录 C 和行为编辑器，而不能继续允许用户选择推导分类作为条件。

**新增验收：** 当轮新增唯一风险依据时按选定语义正确触发；当轮撤回唯一依据时不因旧推导误触发；同轮前序行为改变数据，不影响已经冻结的其他行为条件。记录条件使用的断言和推导版本。

### A03｜高：项目包仍未明确携带当前断言事实及映射来源所有权

**性质：上一轮 R10 部分修复后的实质残留。**

**原文位置：** [FR-006，L260](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:260)、[FR-304，L363](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:363)、[FR-1000，L567](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:567)、[数据对象，L654](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:654)。

导出清单已经明确原始文件、当前推导结果和历史记录可选，但没有明确当前断言事实，以及维持映射替换和人工冲突所需的来源、所有权信息。FR-006 已将本体定义与断言事实分开，不能依靠“本体”一词隐含覆盖全部数据。

**最小反例：** 用户手工创建一台设备，再导入一批映射事实并手工修正其中一个受管名称。导出时不携带原始文件。另一设备按目前列出的清单导入，可能没有手工设备事实，或虽然还原了三元组，却丢失“由哪个映射管理、哪里曾经人工修改”的记录。此时查询和重跑冲突检测无法等价。

这不表示所有实现都会丢数据；问题是不同实现可以依据同一清单交付不同内容，现有迁移验收无法排除损失状态的实现。

**建议补入 FR-1000：**

> 完整项目包必须包含当前断言事实，以及维持映射重跑、来源定位和人工冲突检测所需的来源与所有权元数据。物理上允许与本体保存在同一文件，但清单必须明确组成。未携带当前事实的包只能标为模板包，不得承诺恢复当前项目状态。

如首版只做一种项目包，可以只支持完整项目包，无需为了本条新增两套导出流程。

**新增验收：** 在设备 A 创建“手工事实＋映射事实＋人工修改冲突”，导出并在设备 B 导入。比较断言事实、查询结果和映射来源；重新关联同一源文件后重跑，设备 B 应识别与设备 A 相同的冲突。

同时建议分开显示三种能力：**恢复当前项目、重跑原始映射、重放沙盘运行**。它们需要的输入不同，不宜只用“有没有原始文件”统一判断全部能力。

### A04｜中：项目导出允许选带业务数据，安全验收却禁止所有“敏感正文”

**性质：功能条款与验收条款冲突。**

**原文位置：** [FR-1000，L570](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:570)、[FR-904，L561](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:561)、[12.5，L825](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:825)。

FR-1000 允许用户选择携带原始数据、历史输入和 Agent 会话；12.5 则要求“项目导出、普通日志和最小外发记录均不包含 API Key 或敏感正文”。“敏感正文”的范围没有定义。

**最小反例：** 用户明确选择导出含企业业务内容的原始文件或会话。这符合 FR-1000，却可能违反 12.5；研发可能因此自行删数据，测试也可能拒绝完整项目包。

**建议将 12.5 拆成明确对象：**

> 所有项目包、报告和日志不得包含 API Key、密码等敏感凭据。最小外发记录不得保存业务正文或完整工具结果，普通日志按脱敏规则处理。项目包与报告可以包含用户明确选择的业务数据，导出前必须展示实际数据范围；未被选择的可选内容不得写入。

如果实际产品意图是禁止导出任何业务敏感数据，则应反向收窄 FR-1000，并明确判定规则。不能同时保留两种相反承诺。本次不建议增加复杂敏感数据分类平台。

**新增验收：** 经用户选择的业务数据可以完整迁移；凭据仍被排除；未选 Agent 会话不进入项目包；最小外发记录不保留正文。

### A05｜中：固定验收基线中的设备 003 和用例重置规则尚不完整

**性质：已有验收表的可复现性缺口。**

**原文位置：** [G.1，L1088](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1088)、[G.2，L1096](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1096)、[名称约束验收，L1110](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1110)、[G.3，L1118](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1118)。

G.1 仅显式创建设备 001、002；G.2 的告警表引用 003，却未给出其类型和初始名称，之后要求“删除 003 名称，只产生对应违规”。没有完整初始状态，测试人员必须自行补数据。是否覆盖到设备 003，也依赖所选验证范围和类型依据。

此外，G.2 先关闭 A01、随后检查“初始推理”、再删除 A01，G.3 又使用 A01 新增事件。若逐项连续执行，前一步修改会影响下一步；若各自独立执行，则必须明确还原基线。

**建议：**

- 提供最小完整基线：设备 001/002/003 的类型与名称、告警及关联、所用本体公理、约束、规则和固定验证范围。
- 每个用例注明“基线版本—操作—预期输出”，默认独立还原；需要连续步骤的用例应显式标注。
- 行为用例给出事件提交前的场景状态，明确 E01 对 A01 做什么数据变化。
- E.5 除积压与完成数量，还应给出稳定工单 ID 和逐轮应完成的对象集合，才能验证既有的“逐轮状态完全一致”承诺。

**建议的用例组织示意：**

| 用例 | 起点 | 操作 | 预期 |
|---|---|---|---|
| Q-01 | 恢复 G-base | 查询未闭环高危告警 | 仅 A01 |
| Q-02 | 独立恢复 G-base | 将 A01 关闭后查询 | 空结果 |
| V-01 | 独立恢复 G-base，003 有明确类型和名称 | 删除 003 名称并按固定范围验证 | 只有指定必填违规 |

具体数据文件仍可由后续案例交付物完成；需要现在明确的是完整基线与重置契约，避免让不同团队各自猜测。

### A06｜中：模型接收端变更后，旧外发授权是否仍有效未定义

**性质：授权目标身份及失效边界未明确，不是已证实的泄露。**

**原文位置：** [FR-900，L541](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:541)、[FR-902，L551](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:551)、[附录 F，L1064](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1064)。

V0.2 已要求授权绑定目标模型服务，并允许同一范围复用授权；但未说明“目标服务”的身份是显示名称、配置 ID，还是实际接收端点。

**最小反例：** 用户授权服务配置 A 发送项目上下文，随后只修改 A 的 Base URL，名称和配置 ID 不变。若旧授权按配置 ID 复用，即使最终发送字段都在授权范围内，也可能发往新的接收方。

**建议补入 FR-902/附录 F：**

> 授权绑定实际接收端点及会改变接收方的配置版本。修改 Base URL 或复制为另一个服务配置时，不继承旧外发授权；首次外发重新展示目标并确认。仅修改显示名称可保留原授权。

这只针对接收方变化，不要求每次模型请求重新确认，也不需要扩大受测模型范围。

**新增验收：** 授权端点 X 后将同一配置改为 Y，下一次请求不能直接复用 X 的授权；只更改显示名称则无需无意义地重新授权。

## 3. 两项建议补充

### A07｜在 M0 明确 RDFS 与非递归规则如何组合

**位置：** [FR-501，L405](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:405)、[FR-505，L427](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:427)、[附录 C，L950](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:950)。

“不支持递归”已经限制了范围，但没有明确 RDFS 推导能否触发自定义规则、自定义规则输出能否触发下一条规则或 RDFS。现有文字可以被合理实现为完整计算受支持规则的结果，因此不将其直接认定为错误实现。

**建议在附录 C 补一句语义选择，并增加三组组合测试：**

1. `High/Open → HighRiskEquipment → NeedsInspection` 两条规则链；调换保存顺序，结果与依据应符合固定语义。
2. 设备先经 RDFS 获得某类型，再满足自定义规则条件，明确是否应触发。
3. 两条规则形成相互依赖循环时，按“不支持递归”约定拒绝或明确报告不支持；不能仅逐条检查而漏掉组合循环。

对支持的规则链给出依赖计算顺序或等价的可观察结果即可，不必在 PRD 指定引擎算法。若选择限制规则读取范围，也应明确说明，避免用户按更强的组合能力理解。

### A08｜HTML 报告需要把导入内容当作文本安全显示

**位置：** [FR-1001，L575](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:575)、[FR-800，L503](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:503)、[安全要求，L718](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:718)。

本版明确首选 HTML 报告，但“不允许导入内容提升 Agent 权限”还没有规定这些内容被写入 HTML 后怎样显示。如果实现直接拼接设备名称、备注或模型解释，原本是数据的标记内容可能被浏览器解释为页面内容或脚本。此项是输出边界建议，未验证存在实际漏洞。

**建议最小条款：**

> 用户导入值、查询结果和模型文本默认按文本安全显示；如允许有限富文本，应进行相应净化。导出报告不得执行来自业务数据的脚本或因其中的标签自动加载外部资源。P0 报告资源应随文件提供，保证离线打开。

**新增验收：** 设备名称包含 `<b>设备A</b>` 时按既定文本策略显示；包含脚本、事件处理属性或外部资源标签的测试值，不应执行或自动外联。正常中文、引号和换行仍能正确显示。

输出编码与富文本净化应依据实际显示位置选择，不能只依靠一个通用替换规则。这一技术边界可核对 [OWASP XSS Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html)。

## 5. 建议加到测试方案、无需另报为产品缺陷的反例

以下情况已经能够由现有不变式约束，增加用例即可，不必继续扩写一轮重复需求：

- **过期任务晚完成**：V1 推理尚未完成时项目变为 V2；V1 结果完成后不能被标为 V2 的当前结果。
- **独立重放与快照续跑**：独立重放恢复相同初始事件消费状态；显式从快照续跑则保留该快照的消费记录，不能重复建单。
- **映射预览后人工修改**：预览后发生人工修改，提交时仍必须满足既有冲突保护，不能用旧预览覆盖。
- **完整迁移后再次编辑**：导入后执行修改、查询、映射重跑和撤销，仍满足与原项目相同的数据与恢复规则。

本轮也不重复把首发平台、容量、团队资源、引擎范围和受测模型列成新增缺陷；它们在 Q2～Q9 中已有负责人角色、时点和决策产物。
