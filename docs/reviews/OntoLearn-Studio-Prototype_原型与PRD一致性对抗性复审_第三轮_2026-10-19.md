## 1. 本轮修复验证（3/3 通过）

### 1.1 C-05 残余：概念表行级操作补齐 ✅

5 个概念行（设备 / 告警 / 维修工单 / 高风险设备 / 运维人员）的操作统一为 **编辑 / 复制 / 删除**。

- FR-200 要求的"创建、编辑、复制和删除"至此全部可见（创建 = 页头"新建概念"主按钮）；
- "删除"与第二轮已验收的"02 本体构建-删除概念确认"屏形成完整路径：行内删除 → 影响确认（8 处引用分解：2 个属性 / 3 条事实 / 2 条规则 / 1 个查询，与概念表"删除前影响"文案一致）→ 取消并保留 / 确认删除概念；
- 复制操作补齐后，概念管理四个动作在单一行内聚齐，无悬空功能。

### 1.2 N-01：install_date 样本值统一 ✅

"03 数据映射-选择数据"字段检测表的 install_date 样本值由 2025-11-02 改为 **2024-01-15**，与"03 数据映射-预览执行"的输入样本（2024-01-15 / 2024-02-20）及生成 RDF（`:installDate "2024-01-15"^^xsd:date`）取齐。同一向导第 1 步与第 3 步的数据链条自洽，B-06 修复时引入的值矛盾消除。

### 1.3 N-02：NL 草稿数据范围口径说明 ✅

"04 查询-自然语言草稿"的范围说明改为：

> 数据范围：断言事实（草稿默认；执行前可切换为断言事实＋当前推导结果）

- 消除了与"04 查询-结果 / 04 查询-保存查询"（断言事实＋当前推导结果）之间的表面口径矛盾；
- 同时明确了"草稿默认 → 执行前可切换"的交互语义，符合 FR-401"数据范围不得隐藏、始终可查"的要求。

### 1.4 N-03（极低，未改，维持可选级）

快速介绍第 6 步编号徽章节点名仍为 `Quick Step Number 5`，渲染内容正确显示"6"，仅影响编辑器内可读性。不影响交付展示，维持"可选"级。

## 2. 连续两轮未处理的项目（需要决策）

以下 3 项在第二轮报告第 6 节已列为"发布评审前必须处理"，本轮覆写数与渲染文本与 v2 完全一致，无任何变化。

### 2.1 B-03 / B-04（含同族 Bottom Status 徽章）：占位文本"状态"

**现状**：顶栏"自动保存"徽章、Agent 面板"模式"徽章、底部状态栏左侧徽章，在全部 30 余个工作台屏幕仍渲染占位词"状态"（三个 ref 节点 VVbfi / SvPUC / bybVu 的覆写数均为 0，自身也无 descendants）。

**为什么重要**：

- 三处位于每个屏幕的固定骨架位置，是演示和评审时最先被看到的细节；
- Agent 模式徽章是 FR-802"导师模式 / 项目模式"在整个原型中的**唯一**潜在可视化位置，目前该产品能力仍无任何界面表达；
- 1280 响应式稿已存在"已自动保存"的正确文案，证明修复只需批量覆写，无设计分歧。

### 2.2 A-01 残余：流程页主动作无具体文案

**现状**：30 个工作台屏幕的底部 `[Next Primary Action]` 槽位仍统一显示占位词"主动作"（覆写仍仅为 enabled 布尔值：25 启用 / 7 禁用）。PRD 8.3 点名的"预览映射、执行查询、运行检查、比较场景"在对应页面依然不可见。

**修复证据链已完备**：

- 1024 响应式稿同位置正确写了"预览映射"，1280 稿写了"保存查询"——具体文案本应是主尺寸稿的终态；
- v2 已完成按屏启用/禁用逻辑，说明该槽位被当作真实按钮对待；
- 剩余工作量仅为：为各流程屏填入具体动作文案（预览执行→"执行映射"、模板与可视化→"执行查询"、检查总览→"运行检查"、场景配置→"运行场景"、场景对比→"比较场景"、导出项目包→"导出项目包"等）。
