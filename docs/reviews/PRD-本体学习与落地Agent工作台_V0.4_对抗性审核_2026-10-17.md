## 本轮建议

以下“低风险”指审查意见严重程度，与 PRD 的 P0/P1/P2 功能范围无关。

### C01｜低风险：固定 B-06 的执行顺序，确保能检出错误的条件读取

**位置：** [G-behavior 的 X/Y 定义](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1167)、[B-06](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1213)，排序依据为 E.1 第 1030 行。

冻结快照的需求已经正确，但样例没有固定 X/Y 的优先级。如果 Y 优先级高于 X，Y 会先读到 false 并生成通知，随后 X 写入 true。此时，错误地逐个读取可变状态的实现，也会得到“一张通知、最终 P=true”的预期结果。

| 执行顺序 | 正确读取冻结快照：通知数 | 错误读取可变状态：通知数 | 能否区分 |
|---|---:|---:|---|
| Y → X | 1 | 1 | 不能 |
| X → Y | 1 | 0 | 能 |

**最小修改建议：** 在 G-behavior 增加：

> X、Y 均启用，优先级均为 0，行为标识分别为 X、Y；按 E.1 排序，X 的动作先于 Y 执行。B-06 必须验证该动作轨迹，以及 Y 仍依据动作执行前冻结的 T1.P=false 生成一张通知。

这只固定测试输入，不改变现有条件冻结语义。

### C02｜低风险：B-10 使用与事件 ID 排序相反的输入顺序

**位置：** [E.1 排序规则](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1030)、[B-10](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1217)。

当前用例按 E-M3、E-M4 输入，输入顺序与事件 ID 升序一致。错误实现即使跳过“事件输入序号”、直接按事件 ID 排序，也能通过。两个事件修改不同工单，仅检查最终状态和两张通知无法识别此错误；错误排序本身也可以稳定重放。

**最小修改建议：** 保留事件载荷对应关系：E-M3 更新 W-test=S3，E-M4 更新 W-other=S4；改为先提交 E-M4，再提交 E-M3。除了最终状态和两张通知，明确断言执行轨迹为：

> `(E-M4, B-multi)` → `(E-M3, B-multi)`，每个实例内部仍按动作一、动作二执行。

这样才能验证“输入序号优先于事件 ID”，而不只是验证重复运行结果相同。

### C03｜低风险：明确 G-behavior 的执行范围与结果检查时点

**位置：** [G-behavior](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1159)、[B-10/B-11](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1217)，关联 [E.2 资源阶段](/Users/kyle/Documents/工作/知爻/本体/PRD-本体学习与落地Agent工作台.md:1045)。

行为基线没有说明是否运行完整轮次，也没有固定资源产能和最终状态的检查时点。B-10/B-11 期待工单状态为 S3/S4/S1；若测试使用完整轮次且资源处理规则继续处理这些工单，轮末结果可能不同。

FR-603 的样本测试并未明确必须执行完整沙盘，因此这里属于**测试边界待明确**，不能据此认定资源阶段必然覆盖状态，或判为新的产品语义冲突。

**建议采用一种固定配置：**

> G-behavior 中的用例运行 1 个完整轮次，资源采用“直接设置每轮产能”方式，产能为 0；成功用例核对轮末提交状态，失败用例核对回滚后的已提交状态。B-07 与 G.4 单独使用具备处理产能的完整轮次配置。

若实际行为测试界面只执行到行为阶段，也可在测试文件中明确这种边界和检查时点；不要由不同测试人员自行选择。建议优先使用前一种配置，便于沿用 E.2 的提交与回滚语义。
