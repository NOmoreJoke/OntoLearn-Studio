## 1. 七项优化逐项决定

| 建议 | 决定 | 价值与落地边界 |
|---|---|---|
| 1：S1 增加合成规模阶梯 | 采纳 | 在 S1 先暴露建图/查询路线风险，避免等到 B1 才发现。至少两档，100× 选做；用独立 ID/命名空间扩展真实三元组数，固定生成器、查询与设备/版本/测量口径，与 B1 复用。Q5 未定不设业务通过线；超时/OOM 如实记录，风险阻止无依据的路线冻结。 |
| 2：S2 契约独立评审门 | 采纳 | 写在批次 1 退出、批次 2 进入处，而不是批次 2 的“进入下一阶段”列。对照 S1 故障用例审查 schema、恢复、提交与取消；设计通过不等于实施通过。 |
| 3：通知身份与错误参数 | 采纳 | 明确 jobId 跨项目/重启唯一，项目任务通知带 projectId 并核验归属，会话事件另定义。可选 params 按错误码定义白名单、类型和大小；承载安全位置参数，不能成为原始业务数据/异常的通道。 |
| 4：CSP 交付策略选择 | 修正后采纳 | 固化仅 meta 或 meta/header 并存方案并验证。原计划已经要求单配置生成开发/生产变体，变体与交付渠道不能直接算作“三重来源”。有兼容疑问时做最小对照即可，不为比较强制维护两套实现。此次未选择或改动实际策略。 |
| 5：机器可读失效规则 | 修正后采纳 | S1 定义共享规则/原因码及正反例，供后续引擎、UI、Agent 消费。D.2 第九行明确模型/提示配置变化不使领域结果过期，不能机械生成九个 staleReason。按实际依赖失效；历史、失败、取消和缓存实现兼容性分开表达。 |
| 6：已提交进度引用 | 采纳 | 逐轮任务定义 committedProgress（运行、最后提交轮次、快照），零提交显式 null，不适用另区分。依据 S1 同事务的提交记录恢复；cancelled/failed 仍可含历史已提交点。此前某轮提交不等于整项任务 succeeded。 |
| 7：Q3/Q6 回答时点 | 修正后采纳 | 批次 2 附近设建议决策检查点，待负责人确认，不擅自新增硬期限。Q3/Q6 原本就阻塞 M0 完成；Q6 依据实际代表样例，不为赶时间冻结。未答复不视为默认同意。 |

## 2. 对问题定级与原型论证的修正

本轮开始时确有 4 个修改文档及 2 个未跟踪路径，HEAD 仍为 e628f5e；存在交接、引用与备份风险。但本地未提交不意味着无法运行检查，报告自身也复跑了检查；当前未发现丢失、错误分发或协作冲突证据，不宜直接等同 P1 故障。

### P1-B：采纳限定实例的修复方向，否定计数推出误伤的结论

原型 JSON 独立核对结果：

| 共享组件 | ref 数 | 已显式覆写 label 的实例数 | 唯一未覆写实例 |
|---|---:|---:|---|
| Badge / Success（eLlED） | 51 | 50 | SvPUC（AppShell 内） |
| Badge / Info（ic7X0） | 34 | 33 | VVbfi（AppShell 内） |
| Badge / Neutral（rZAMY） | 25 | 24 | bybVu（AppShell 内） |
| Button / Primary（agBlV） | 19 | 18 | bhL4U（AppShell 内） |

这意味着“修改通用默认文本会导致 51/34/25/19 处无关实例一起变文案”的论证不成立：其他实例已有覆盖，引用计数本身不足以证明误伤。第四轮路径 A 的文字是编辑 AppShell 本体，也不能直接解释成修改通用 Badge 定义。仍应优先限定 AppShell 内 ref 的 descendants，减少改动面；这里是风险控制建议，不宣称默认修改已经造成回归。

顶层节点共 56 个，含组件定义；AppShell（aLI9i）实际有 32 个直接引用，不能称为“传播到全部 56 个屏幕”。第四轮填充表同时含具体动作、禁用页与待按语境决定项，亦不足以冻结“18 屏”的准确改动范围。

JSON 可写且存在 descendants 不能替代实际渲染验证。后续应先验证一个实例的实际显示，保留逐屏启用/禁用覆盖，核对项目模式例外、保存/错误状态及单一主动作，再做全量结构/解析文本差异与编辑器视觉检查。原型里的“已自动保存”是设计状态，不证明运行产品实现了保存。实际应用必须由保存结果驱动，不能用改字替代功能。

两份 .pen 当前 SHA-256 均为 `5552936777cfb75deac1437f20cd0b00640f30387fc912a04855ce88c7c39c57`。后续有意修改后再同步副本与 manifest；该清单脚本只检查仓库副本与记录哈希，三方一致仍需显式读取外部原件比较。通过哈希检查不代表语义验收通过。

原型三项遗留仍开放，已在交接清单细化修复与验收路径。未修复也未执行“第五轮验证”，不声称审查闭合；PRD §17 罗列后续设计交付物，没有明确要求三项徽章问题必须阻断所有后续设计工作。

P2-C 的 finish 后继续追加输出确实存在；“无内存危害”没有专门实测支撑，且 finish 会清除 timer，不能继续引用该定时器作收尾兜底。暂不修改单请求适配器，S2 增加追加前字节限额、多字节/多 chunk、终态后 chunk 的跨端测试要求。
