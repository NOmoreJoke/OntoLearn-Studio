六、推送与合并门禁

只有以下条件全部成立，才能推送并合并：

- 本功能验收与必要验证通过；
- 两个指定模型对同一候选版本均明确通过；
- 阻断问题全部关闭；
- 其余建议均有处理结论，且不影响双方的通过判断；
- 待推送实现与受审实现一致。

满足门禁后：

1. 将 feature 分支推送到已核验的远端，记录提交 SHA 和推送结果。
2. 优先创建指向 dev 的 PR，附功能说明、验证结果、两份最终通过报告及意见处理记录。
3. 遵守仓库实际分支保护和 CI 要求，不绕过检查。若使用仓库允许的其他合并方式，同样保留可追踪记录。
4. 若 dev 已变化，导致基线更新、冲突解决或候选内容变化，更新后重新验证并完成双模型独立审查，不能直接沿用旧通过意见。
5. CI 失败需要修改实现时，也必须回到验证与双审循环。
6. 合并后核验远端 dev 确实包含本功能，记录 PR 或合并记录、合并 SHA 与必要验证。
7. 完成当前迭代记录并结束该开发会话的功能目标，总控核验后再新建下一迭代会话。
