# 指定推理结果的纯投影与真实接线边界

依据：I03 冻结候选 `f574a7234923f28e9356a45a17253803e7602e06` 中 `docs/iterations/I03/I05-semantic-boundaries.md` 的分层投影要求，以及总控本轮明确交接。该 I03 候选仍在原双审流程中，本记录不采用其为已批准契约，也不改写共享 schema 或新增公共业务方法。

## 生成与选择分别执行

`prepare_validation_scope` 是生成入口：从本次断言 / ontology 和显式规则计划调用真实 `reason()`，得到新结果后交给相同投影器。

`project_validation_scope` 是选择入口：接收明确指定的完整已有推理载荷及生产上下文，验证内部一致性并产生事实 / 公理视图。它不调用 `reason()`，不补齐缺失的推导或依据，不用当前启用规则替换该结果。空结果是有完整固定结构的真实计算结果，和缺少载荷不同。

完整原载荷通过 `ValidationScope.reasoning_result` 原样保留，比较与分图只使用独立规范键。全部原断言留在 facts；领域派生类型和规则事实加入 facts；原始 / 派生公理及来源另留 ontology。展示用 provenance 不反向修改原结果对象。未增加规则链或新业务能力；投影保留原词法的修复使用 `i05-finite-3` 记录可观察行为变化。

## 本地可核对的边界

- `reasoning_source` 是私有生产上下文摘要，含有限语义版本及原断言 / ontology / 实际生产规则计划的规范摘要。投影器比较完整输入，包含未被某条依据使用的事实；输入或生产计划不一致则停止。该参数不是公开 DTO，也不是来源真实性证明。
- 固定根字段与每条依据字段精确检查；三元组支持本引擎 native tuple 及 JSON list，独立归一化，拒绝缺项、多项、错误类型和非规范 RDF 项。
- RDFS 输出唯一，并与 RDFS 依据一一对应；依据非空且属于原断言＋原 ontology。只接受本有限引擎实际可产出的类型与子类结果形状。
- 规则输出与依据结果集合完整相等；允许同一结论有多个不同真实匹配。每条依据按原 `when` 次序检查同一变量绑定及 `then`，规则只读原断言＋原 ontology＋RDFS。某事实同时原已存在且又被规则输出仍可读取；仅由本轮规则新产生的事实不能触发第二条规则。
- 规则原始 basis 必须恰好等于其输入各原始依据的并集；未知规则、错误绑定、缺证据、外来依据、schema 输出、错误角色或警示不一致均停止，不过滤后成功。
- 累计投影项预算与最终分图量预算是工程保护，非容量通过线。缺失 / 损坏的可信选择上下文或载荷走安全内部错误，不提示用户删除数据、重选合法 scope 或执行新推理掩盖失败。

这些检查证明给定载荷的内部一致性及视图保留关系。它们不独立证明每条 RDFS basis 可推出结论，也不枚举全局推理来证明“没有漏掉另一个可能结果”。重新求值检查并补齐选择将破坏选择语义，因此不这样执行。

## 真实样例与反例

同一真实 ontology 为 CriticalPump→Pump→Equipment，断言 unit 为 CriticalPump 且关联 High/Open 告警；名称缺失。先实际计算不含 R-risk 的结果，再实际计算包含 R-risk 的不同计划结果。前者仅使 unit 成为 Equipment 名称约束目标，后者额外使其成为 HighRiskEquipment 名称约束目标。

明确投影前者经过 JSON 往返的完整载荷，得到一项名称违规，风险形状目标为空；后者有两项名称违规。完整目标 / path / constraint / sourceShape、原载荷和输入不变均比较。单元测试将 `reason()` 设置为一旦被调用即失败，选择入口仍能完成；这只是禁止重算的调用断言，推理结果来自此前真实库执行，不是预制结果或任务替身。

共享源码 / 包内样例另检查缺载荷、缺 RDFS 依据、仅无关事实变化及生产规则计划变化均安全拒绝。单元覆盖多依据、原 ontology 作为规则条件、原已存在结论、伪造二阶规则依据、未知规则、错误绑定 / 角色 / 原始依据、空结果与未选推导混入载荷。

这里“较早结果”只表示此前真实纯计算得到的不同计划载荷，不声称已经存入 Store、存在历史 resultId、通过授权或被用户在产品中选择。

## I04 仍须实际完成

实际 Store、内容寻址读取 / 摘要、项目与快照 / definition / parametersHash / resultId / producer implementation、显式历史选择 / current 状态及权限的权威原子绑定均归 I04。I04 必须先解析已核验生产者输入与定义上下文，再把其对应的图、完整结果和本地生产摘要交给投影器；不能把 renderer 自报的摘要当成授权。

本地摘要不等同于 I03 blobRef 的存储字节摘要，不能混用两种哈希域。它由实际已核验的生产输入计算，用来比较投影请求的完整图与计划。外层绑定未成立时，不调用投影器并宣称已通过；读取失败、载荷回收、版本不兼容或身份不匹配不能静默重算。

真实 I03/I04 合并后仍需刷新基线，按原要求完成任务、持久化、取消、错误、实际选中结果、包内与窗口联验及双方新全范围审查。本记录没有替代这些门禁。

内部独立审查曾实测发现默认解析规范化 `01` 和损坏载荷 surrogate 裸异常两项。当前使用固定内存 Turtle SinkParser、局部保留词法的 sink，不更改 RDFLib 全局设置；每行严格匹配且先检查 UTF-8。真实原词法与非法编码反例补齐并定向关闭，未用新增1MiB行门去额外收窄源Graph已经可产出的值。实际验证版本以状态和证据清单为准。
