# 可信投影、来源能力与私有排除

## 1. 一次一致读的业务投影

建议P-ExportRequest仅表达用户选择：源项目、full/template、四选项及子范围、报告范围。renderer不提交SQL、文件路径、DB名、privateroot排除数组或“事实已可信”布尔值；main验证可信窗口/mainFrame、项目/请求/代次后建立不可序列化内部上下文。实际业务服务名称与协议由唯一owner批准，不按P名称注册能力。

建议T01一致读服务在同一受支持事务快照中固定：projectId、domainSnapshotRef/revision、checkpointRef/operationSequence、application/metadata/draft/learning CAS、业务schema/canonical/reader/writer版本和实际选项范围。返回不可变P-ExportProjection，其四类内容明确分开：

| 内容             | 必要字段与证据                                                                                      | 禁止替代                                               |
| ---------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 业务集合         | 每类型strict payload、实际记录数/集合digest、schemaRef；含全部必需集合和被选集合                    | 手写空数组、任意对象dump、全SQLite、按目录复制         |
| coverage/closure | 固定根与typed引用、source→portable digest映射、缺口/选项冲突、安全分类结果                          | 源完整checkpoint通过即视为裁剪投影通过                 |
| 可选附件清单     | sourceObjectId、project/generation、格式/工作表、字节数/hash、sealed状态、未打开的main-only只读引用 | renderer/包内路径、文件名匹配、follow目录、共享env读取 |
| 来源证明         | 生产owner/schema身份、固定snapshot与CAS、执行语义/工具检查引用及受信调用链                          | hash/signature字段自报、模型文字、客户端“独立完成”声明 |

流式编码可以分块，但所有块必须来自同一固定业务快照。源项目随后改变时：已固定的内容仍只能按已预览snapshot导出，若UI要求“最新当前”或确认绑定的代次已变化则旧确认失效并重新预演；二者具体交互政策见F10，不把多个时点拼成一个包。资源预算超限必须取消本次而非裁剪业务集合。

可信导出来源是实际本地T01/T09/T08/T07服务返回的批准投影和来源能力。任意外来包始终是不可信输入：其hash只证明字节自洽，不证明生成者、来源归属或学习真实性。没有已批准的外部证明机制时，不把包内actor/工具日志当本机真实学习事件；保留origin事实的“导入/未验证”标识。是否引入签名/信任链属于F09，不凭提案添加PKI或企业用户系统。

## 2. 字段白名单与边界

| 可移植业务内容                                                    | 允许理由                                           | 始终排除                                                                                             |
| ----------------------------------------------------------------- | -------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 定义、事实、来源/owner、managed/tombstone、业务版本和必要控制证据 | 当前状态/冲突/撤销语义所需，由T01 typed schema证明 | DB/userData文件、未知表/未定义字段、任意路径、活跃claim/context/调度状态                             |
| 学习task/attempt/check/hint/assistance最小业务记录                | 保留真实辅助事实与完成分类；不能因会话未选洗白     | 全会话正文或工具结果伪装audit、I06 profile audit/发送ledger、endpoint/principal/binding/ref/配置版本 |
| 用户已选择会话/历史/原文件/推导                                   | FR1000明确选项，范围可检查                         | 未选部分、私有凭据/密文、运行发送授权、可复用grant/preview/invocation/catalog                        |
| 合法项目/课程配置、业务草稿                                       | 恢复当前项目状态；由T01白名单逐字段证明            | profile配置、密钥库引用、endpoint credential主体、配置journal/pending、模型网络权限                  |

“audit”字段名不能决定去留：业务assistance记录与I06私有audit按生产owner、schema、字段、用途及实际引用分别判断。必要业务控制证据不可因名字包含audit/operation而一刀删；不透明audit对象也不可一刀放行。active job/grant不能从历史业务operation证据恢复为执行能力。

需要导出来源行身份或managed业务值时，这些可以是已授权业务内容，但不代表允许整行原始数据。typed schema明确每个值的恢复用途；未选raw的source元数据只保留重关联/冲突所需部分。若正确恢复必然需要含敏感凭据的值，则不能默默脱敏后保留“同等恢复”承诺，应按F08阻断并说明业务语义损失。

## 3. I06私有边界与guard-before-IO

仍沿已有I06设计接受的两步能力边界：main native picker只给候选；I06先以metadata-only方法验证完整私有inventory，再批准prospective范围；取得实际handle/parent/member身份并扩展绑定后才内容IO。不会把path+assertSafe令牌返给T10后自行reopen，也不把fault hook当权限检查。

I06私有inventory须由其唯一owner交付profile epoch/revision、完整性/预算、私有整根及所有后代、journal/pending和密文原件的元数据身份、原子发布/失效屏障和退役规则。T10只获得受限操作能力或固定拒绝，不读取inventory内容、私有字节/hash来找别名。未知、不完整、超预算或服务故障不能按空私有根放行；只拒本次transfer，本地Store/窗口继续工作。

| 范围           | 在首次内容IO前的必要能力                                                         | 后续使用                                                                                                              |
| -------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 输入包         | 候选经I06排除私有根/祖先后代/已登记硬链接别名，经受控IO形成有界不可变P-InputSeal | 稳定handle仅固定对象身份，不固定字节；解码、预演、附件准备共同消费该封存快照并绑定其digest，确认后不重读原路径/handle |
| 原始source     | T03/T01归属与sealed证明加I06等价排除能力                                         | 仅读清单对象，project/generation/hash/长度绑定；Python不获私有inventory/任意路径                                      |
| 输出final      | 单一新文件、实际父目录及最终发布范围的受控能力                                   | 不覆盖发布；最终发布前复验，成功后不倒退为取消                                                                        |
| staging/unpack | 创建前批准精确任务范围，创建后绑定身份；默认不解包                               | 固定白名单成员和身份绑定非递归清理；未知文件保留，cleanup pending可对账                                               |
| import附件存储 | 唯一owner控制的不可见新对象命名空间及durable sealed证明                          | 不因包内路径或包内对象ID授予源机器路径能力                                                                            |

InputSeal存储、prepare/pin及恢复日志均在唯一owner受控范围，跨崩溃保留与GC接管按import-plan-and-receipt.md；它们是本机操作材料，不进入可移植业务包。稳定输入handle、T03进程内source proof和持久pin各自保证不同性质，不互相替代。

bootstrap及实际身份绑定失败都不能在允许前发生read/hash/mkdir。跨await、profile/project/window代次、目标重选或重新打开都重验；无法证明平台原语足够则相关操作拒绝，不以关闭沙箱或一次O_NOFOLLOW/fstat宣称目录相对原子confinement。持续同UID恶意namespace攻击不冒充已解决；Windows/macOS各自支持边界和实际原语待I06批准/验收（Q2、F11）。

## 4. Source封存、缺失与重新关联

T03需提供经批准的source对象合同：项目/代次、对象ID、格式/工作表、长度/hash、封存版本/有效性、可消费次数/取消和失效、main-only有界读取能力及固定错误。payload中的source描述不是FS句柄，路径显示字段不是重开能力。

导出时只有在选择raw后才能读取字节；封存对象变化、重关联或长度/hash不匹配使对应预演失效。导入后无raw时保存来源元数据及缺依赖状态，恢复已有断言/owner/冲突基线；不新建空source冒充存在。用户重新选择同源时先核字节/格式/身份规则/版本再开放对应映射重跑。不同内容或转换格式可能仍可由用户选择为新源，但必须重新预演映射差异/冲突并确认，不能默认等同原文件（F12）。

## 5. 自由文本与凭据政策

系统私有材料排除和用户业务正文敏感内容是两道不同问题。I06 inventory/IO能力能阻止系统密文、配置与授权原件进入包，不证明事实、文档、CSV、会话或模型文本内没有用户粘贴密钥。生产禁止读取vault真实秘密作匹配，也不能只搜apiKey字段名后宣布通用DLP。

F08必须批准具体字段/来源范围、可检查介质、识别/拒绝/脱敏规则及用户交互。建议优先采用已登记业务类型+固定敏感形状检测作阻断提示，记录检测版本和“不能完整检测未知秘密”范围；检测不能作为唯一排除证明。项目数据、完整原文件、保真恢复与脱敏冲突时拒绝相关导出/范围，或用户显式选择另一个已获批且不承诺等价恢复的材料；不得把用户点击“仍导出”视为允许违反凭据始终排除。该策略未批准及端到端验收前，不开放真实导出。

错误/普通日志仅保存request/operation摘要、阶段、固定安全码和有限计数/定位引用，不保存原单元格值、业务正文、路径、完整tool response或密钥。需要用户检查业务值时走已授权的受控预演视图，不在错误toast、stderr或最小外发记录dump原值。模型请求授权独立，导出确认不允许网络发送，包内文字、URL或注入指令也不能改变任何权限。

## 6. 证据要求

未来X2在隔离合成profile放置唯一明文标记与真实加密后原件，覆盖实际包各成员、解压/导入数据、manifest/HTML/日志/staging/unpack和失败/取消路径；既查明文也比密文原件字节，不在生产读取真实凭据。X3覆盖相同/祖先/后代路径、symlink/硬链接别名、动态私有后代、重新打开、目录替换、inventory不完整/故障和跨await失效，证明拒绝发生在相关IO前。通过这些也不扩写为识别所有自带业务秘密。
