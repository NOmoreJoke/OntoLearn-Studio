# 学习证据、三能力与正式HTML报告

## 1. 真学习证据的最小投影

T09/T08/T01共同提供实际来源、版本和覆盖的P-LearningProjection，T10不从点击、模型评语或renderer布尔值推学习掌握。建议字段分层：

| 层             | 建议字段/约束                                                                                                                           |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 任务身份与版本 | taskDefinitionId/version、课程/清单版本、goal、可验证completionCriteria、transferTask类别；不是仅名称                                   |
| 尝试           | attemptId、originAttemptRef、taskVersion、开始/结束/状态、实际操作变更或成果引用、对应项目snapshot/revision                             |
| 真实检查       | checkId、工具/能力ID、inputSnapshot/scope、检查器/语义/engine/lock版本、结果/时间、当前/过期/历史/失败取消；检查必须绑定该attempt和条件 |
| 提示事件       | FR101的概念提示/操作提示/部分示范/完整示范、实际发生序号/时间、任务attempt和来源；不凭提示按钮存在推发生                                |
| Agent辅助      | none/partial/complete的真实受信事件、实际接受的ChangeSet或操作证据引用、mode与时间；保留完整代做事实，不带完整会话/密钥/发送授权        |
| 覆盖/信任      | 证据生产owner/schema、assistance/hint/check覆盖范围与完整性、缺失项、imported-origin/local-verified区分；事件缺席不自动证明无辅助       |
| 独立指标       | operationCompleted、verifiedTaskCompletion、independentTransferSuccess分别为带理由的判定；规则版本与依据引用可追溯                      |

具体字段和保留范围由上游固定schema给出。本提案不自建新的task/attempt真相，不把过时/不完整owner输出补成默认false后宣称无辅助。元数据可作为当前learning状态必需闭包，但必须是批准的最小业务记录；与完整会话、运行历史的范围冲突按typed closure规则阻断而非夹带。

## 2. 分类提案及政策边界

FR104至少三类；FR105和11.2明确操作完成不等于独立迁移成功。建议多轴显示，避免单标签吞掉失败或辅助：

1. 先列实际操作完成状态与真实检查状态。未检查、失败、证据不齐/不受信、版本过期或不属于该attempt的检查不能形成“已验证独立掌握”；完整辅助事件即使检查失败也保留。
2. 在确实完成且真实检查符合任务条件时，实际Agent完整代做必须显示“Agent完整辅助完成”，independentTransferSuccess不能为true；完整示范显示“使用完整示范完成”。
3. 发生部分辅助/部分示范及其他提示时保留真实级别，并按获批汇总政策显示使用提示/辅助完成。FR101四级提示如何归到FR104至少三类由F15明确；本提案建议保留明细，避免把概念提示误算完全无提示。
4. 只有真实任务检查成功、范围/版本一致、完整无提示/无辅助证据且满足获批attempt政策，才可列“独立完成”；FR105的独立迁移成功还须是对应迁移任务的真实检查，不从普通任务独立完成外推。
5. 证据未知、导入来源无法验证、旧尝试/检查已不适用时显示“未验证/历史来源”，而不是强行分进独立、提示或示范完成。

这些是待T09/T08确认的判定提案，不修改当前S1私有分类器。跨attempt的先前示范、重试/重置/更换数据后何时允许重新独立，PRD没有完整算法：F16列“当前attempt且显示既往暴露”和“任务级辅助上限”等方案。冻结前不把新attempt或迁移后新ID视为自动洗白；也不擅自判定用户永远不能重新独立。准确保留原记录与关联，未决结果明确未验证。

## 3. 跨设备学习信任

导入时typed重映射保留origin task/attempt/check关联和真实辅助事实；不把foreign actor ID直接当本机用户，不重建假的“本机工具已验证”事件。包内自报checkPassed/independent=true、hash相同或原HTML文本都不是本机真实检查。没有获批跨设备来源验证时，展示导入的历史主张与unknown trust，本机重新执行检查产生新的真实记录，不能覆写旧attempt或擦掉先前辅助。外部签名/可信producer如将来采用，须F09批准信任根、验证与失效，不在本提案虚构。

如果迁移目标本就要求当前学习记录保真，完整包必须交齐上游批准的最小证据和来源状态；不能因为不信任外部主张就丢弃合法业务记录。无法核验影响显示资格，不等于授权删除。独立掌握分类的产品政策仍由对应owner决定。

## 4. 三种能力分别计算

包内声明最多是未受信提示。导入方按本机支持与实际材料为每项输出`materialState / supportState / verificationState / reasonRefs`，不以一个restorable布尔值覆盖全包。最终正式枚举/错误由owner批准。

| 能力                      | 必需材料                                                                                                       | 不能据此承诺的情况                                                               |
| ------------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 恢复当前项目              | full全部核心业务、typed最小闭包、可支持版本/引用/owner语义与原子Store导入能力；无需raw或一般history            | ZIP合法/hash相同、缺owner、只graph、只有当前快照引用但无目标、接口未实现         |
| 重跑原始映射（逐mapping） | 实际sealed/重新关联的正确source、格式/工作表/身份规则、映射定义/生成与受管基线、当前版本、已支持的实际映射执行 | 只有sourceHash、同名文件、raw=true但缺sheet/options/版本，或存在人工冲突尚未解决 |
| 重放沙盘（逐run）         | 该运行的固定输入、配置、行为/规则/场景/事件、执行语义/engine/lock、逐轮预期与真实支持验证                      | 最新状态代旧输入、只有结果摘要、材料齐但版本不支持、未实际执行就说已复现         |

复原当前的合法业务状态不等于当前推导缓存字节已存在。derived未选时：保留被批准的结果身份/范围/输入依赖、原状态和“载荷未携带”事实，按实际引擎支持提供重算；不得把推导变断言、将asserted+derived查询静默改成asserted或把缺载荷说成已获得相同查询结果。payloadAvailability/implementationCompatibility与唯一invalidation staleReason分离，不发明导入过期码。G.6相同查询结果须用同数据范围的真实查询/必要重算核完整集合，不靠count或旧摘要。

有些映射/运行就绪，有些缺依赖时，UI列具体ID、k/n及原因与重关联/重算入口；不得为全包输出无范围的true。外部依赖缺失应明确提示可重关联，不把未知当存在。当前正式接口未批准/未实现之前，本提案不会把现有S1恒false能力翻成true。

## 5. FR1001正式报告的内容合同

P-ReportProjection来自已确认的固定项目/learning/结果快照，默认当前已提交状态；只有用户明确选择才引用历史，所有历史片段显示原版本/范围/状态。各部分一致读取或通过owner批准的固定引用组装，不能拼接未声明的多个“当前”。建议栏目：

1. 项目目标与能力问题、业务假设和当前范围。
2. 任务/attempt完成、实际提示级别、Agent辅助、真实工具检查与独立迁移成功，证据缺失照实显示。
3. 本体定义与断言/推导/场景/历史分层概况，来源与所有权保真说明。
4. 查询和验证结果：完整结果身份、数据范围、input revision/snapshot、依赖/语义/实现版本、当前/过期/历史/失败取消、必要可读证据和未执行项。
5. 行为测试与场景比较：真实逐轮/指标/输入与限制，不把预测当历史预测、模型解释当引擎依据。
6. 主要假设、未解决冲突、能力限制、缺依赖和下一步；全量输出过大时明确受控摘要/分页/未纳入范围，不能把截断说成完整结果。

所有动态值按纯文本输出编码；不执行数据内脚本/事件、iframe或外链资源，不把URL自动变成可加载资源。P0资源随文件或内联且遵唯一CSP authority，不新增任意富文本。中文、引号、前导换行等保真，维持现有安全报告服务的不可覆盖/0600/发布和清理状态，同时正式接入I06实际IO能力，不能把旧fault hook当guard。

报告必须经过F08批准的敏感策略，不能只靠严格DTO字段排除业务文本中的凭据。会话/历史范围仍受实际选择约束；用于报告的学习最小辅助记录按批准业务schema，而不是复制整会话。报告导出不授权外发给模型，最小外发记录也不保存报告正文。

## 6. 判定反例与未来证据

- 点击完成但未执行真实检查：操作记录保留，独立掌握未验证。
- 完整Agent修改让迁移任务成功：操作可完成，辅助=complete，不计独立迁移。
- 先看完整示范失败、后清空UI/迁移新ID：原辅助与attempt关系仍存在，不洗白。
- hint日志/assistance覆盖不完整：不能由“无事件”判独立。
- 导入伪造checkPassed、prompt注入或foreign actor：不变权限，不写本机已验证掌握。
- 当前报告混入旧run结果未标历史、或者缺derived仍声称所有原查询可直接复现：验收失败。

真实T09/T08/T07接入、FR105换数据任务、至少5名未参与开发用户与PRD11.2的实际门、离线核心流程、同版指定双审及平台/CI门均见acceptance-plan；此处没有已运行的学习验收或性能数据。
